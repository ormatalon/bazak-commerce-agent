# Bazak Shopping Copilot V2

A local Chainlit shopping assistant over a fixed DummyJSON product catalog. The parser and responder use `gpt-6-luna`; local multilingual E5 embeddings rank products. Explicit prices/ratings and exclusions remain code-controlled constraints. Alternatives are disclosed per card and do not change the user's saved budget.

Implementation plan: [plan/V2_PLAN.md](plan/V2_PLAN.md). Decisions: [DECISIONS.md](DECISIONS.md). Monitoring runbook: [plan/MONITORING.md](plan/MONITORING.md).

Final evaluation: [plan/FINAL_EVALUATION.md](plan/FINAL_EVALUATION.md). The final 167-case run completed without execution errors; semantic release certification remains pending reviewed labels and calibration. The report includes known recall/compatibility regressions and a same-input V1 comparison.

Code-review fixes and final validation: [plan/CODE_REVIEW.md](plan/CODE_REVIEW.md). With the currency extension, the offline suite has 86 passing tests. Historical evaluation outputs were re-scored with the corrected metrics; no new model responses were generated by that review or the currency extension.

## Setup

These commands are for the `v2` branch and run from the repository root. Use Python 3.12 and [uv](https://docs.astral.sh/uv/getting-started/installation/) to create a local virtual environment. Create a new `.venv` on each machine; a Windows virtual environment cannot be copied to a Mac. V1 on `staging` has separate setup instructions and does not require the embedding model.

### Windows (PowerShell)

Use the virtualenv interpreter: the system `python` command may open the Microsoft Store stub.

```powershell
uv python install 3.12
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt --index https://download.pytorch.org/whl/cpu --index https://pypi.org/simple --index-strategy unsafe-best-match
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

If `CHAINLIT_AUTH_SECRET` is not already configured, generate it locally and copy the printed value into `.env`:

```powershell
.venv/Scripts/python.exe -m chainlit create-secret
```

Complete the shared configuration below, then download the model and start the app:

```powershell
.venv/Scripts/python.exe -m app.embeddings --download
.venv/Scripts/python.exe -m chainlit run app/main.py
```

### macOS (Apple Silicon, macOS 14 or newer)

Use a native Apple Silicon Terminal: `uname -m` should print `arm64`, and `sw_vers -productVersion` should show 14 or newer. If an Apple Silicon Mac reports `x86_64`, open Terminal without Rosetta and create its environment there.

Install uv once using its [official installer](https://docs.astral.sh/uv/getting-started/installation/), then reopen Terminal so `uv` is on `PATH`:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

From the repository root on `v2`:

```bash
uv python install 3.12
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt --index-url https://pypi.org/simple --only-binary torch,numpy
if [ ! -e .env ]; then cp .env.example .env; fi
```

Use PyPI for macOS; the Windows CPU-wheel index is not needed. PyTorch and NumPy use prebuilt wheels, while pure-Python dependencies may be built from their published source distributions. Do not add `--only-binary :all:`: Chainlit's pinned `literalai` dependency has no usable wheel.

If `CHAINLIT_AUTH_SECRET` is not already configured, generate it locally and copy the printed value into `.env`:

```bash
.venv/bin/python -m chainlit create-secret
```

Complete the shared configuration below, then download the model and start the app:

```bash
.venv/bin/python -m app.embeddings --download
.venv/bin/python -m chainlit run app/main.py
```

On later runs, only the last command is needed. No environment activation is required because these commands use its interpreter directly. Stop the server with **Ctrl+C**.

**Intel Macs and older macOS:** the pinned V2 `torch==2.15.0` release has a `macosx_14_0_arm64` wheel, but no native Intel Mac wheel. The setup above therefore targets Apple Silicon on macOS 14+. PyTorch [ended official macOS x86 builds after the 2.2 release series](https://dev-discuss.pytorch.org/t/pytorch-macos-x86-builds-deprecation-starting-january-2024/1690). Native Intel V2 support would require a different dependency plan; installing an older torch alone is not a verified solution for this pinned stack.

### Shared configuration and first run

Edit the ignored `.env` file locally:

- Set `OPENAI_API_KEY` for model calls.
- Choose `APP_USERNAME` and `APP_PASSWORD` for the local login.
- Set `CHAINLIT_AUTH_SECRET` to the generated value. Keep an existing secret if you already use this installation.
- LangSmith is optional: configure `LANGSMITH_API_KEY`, `LANGSMITH_TRACING=true` and the destination in [the monitoring runbook](plan/MONITORING.md) when tracing is wanted.

Then open **http://localhost:8000** and sign in with that username and password. Secrets stay in `.env` and are never committed.

The model identifier is `intfloat/multilingual-e5-small`, pinned to revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`. It runs locally on CPU on both Windows and macOS; this setup does not enable Apple's GPU/MPS backend. The download is required once per machine. The catalog is fetched only if no valid local cache exists. Model calls, uncached currency lookups and enabled LangSmith exports need internet access; product images use catalog URLs.

**Verification:** the Python 3.12 dependency set was resolved for Apple Silicon macOS 14 with prebuilt torch/NumPy, and the Intel wheel incompatibility was reproduced. Resolution is not a native installation or UI test: this project has not been run on a physical Mac in this session.

### macOS troubleshooting

- `uv: command not found`: reopen Terminal after installation, or follow the installer's shell-path instructions.
- No matching torch distribution: check `uname -m`, macOS version and that this environment uses Python 3.12. Do not reuse a Windows or Rosetta-created environment.
- Missing embedding model: run `.venv/bin/python -m app.embeddings --download` from the repo root while online.
- Login configuration error: fill in the three local-login/authentication values above before starting Chainlit.
- Port 8000 already in use: stop the other instance, or run `.venv/bin/python -m chainlit run app/main.py --port 8001` and open http://localhost:8001.

## Retrieval and conversation behavior

- Index two texts per product: title/category/brand and description/tags. Cache both arrays with catalog/model/text-version identity and verify alignment on load.
- Parse independent requests; vague requests can have up to three alternative directions with shared limits. Recent history and shown prices support refinements and comparisons.
- Convert original-currency limits using current published [Frankfurter reference rates](https://frankfurter.dev/). Fetch over HTTP only when a non-USD price bound needs conversion; no API key or extra LLM call is needed. Cache quotes locally in ignored `exchange_rates_cache.json` for one hour. During an outage, use a cached quote only if both its fetch time and reference date are at most seven days old; otherwise ask for a USD budget.
- Pin each currency's quote on its first successful search in a conversation, including after resume. A new chat can obtain a newer quote; an existing chat retains its displayed source/date. These are reference rates, not transaction quotes. Apply strict/inclusive operators after decimal conversion, keep original amounts in state, and disclose any outage fallback.
- Use weighted similarity and a small category boost for rank; relative relevance zones gate each card. Category guesses and positive keywords never filter products.
- A `gpt-6-luna` product-type node then rejects semantically shortlisted products of the wrong type/identity, including fallback candidates. It batches across directions/requests (64 pairs per call), normally adding one model call; broad requests may require more batches. Invalid or incomplete verdicts return an error rather than unchecked cards.
- Filter numeric constraints before card selection. Sort the full qualified inventory, then paginate; do not stop after ten matches. Merge alternative directions by round-robin, deduplicating IDs.
- Fill missing slots with relevant, disclosed rating/price alternatives. Exclusions and semantic relevance never relax. If nothing qualifies, return a useful no-match explanation instead of arbitrary cards.
- Store history, active constraints, shown cards and outcomes through Chainlit's SQLite data layer. V2 state metadata is separate from V1 metadata.

**Calibration status:** initial thresholds are provisional. The owner approved the product-type node after relative-only relevance failed unsupported-type probes. Final feasibility checks and reviewed semantic labels are required before claiming release quality.

## Tests

Offline checks use fake LLM responses and fixed vectors; they never export traces or call a provider. Use a unique workspace temporary directory if the shared Windows pytest directory is inaccessible:

```powershell
New-Item -ItemType Directory -Path .test-tmp -Force | Out-Null
$testTemp = Join-Path (Get-Location) ('.test-tmp/' + [guid]::NewGuid().ToString('N'))
.venv/Scripts/python.exe -m pytest tests -q -p no:cacheprovider --basetemp $testTemp
```

On macOS:

```bash
.venv/bin/python -m pytest tests -q
.venv/bin/python -m evals.experience
```

The same `.venv/bin/python` prefix applies to the evaluation commands below. `pytest` and the experience-fixture validator are offline; `evals.run_evals --live` makes paid model calls.

## Datasets and scoring

The separate [20-case experience pilot](datasets/experience/README.md) covers recommendation usefulness, avoidable non-answers, courtesy, phrasing and follow-up progress. It contains 14 English and 6 Hebrew conversations, including 4 multi-turn cases and 4 legitimate no-match controls. Expectations are assistant drafts, not human-reviewed gold, and the pilot is not automatically included in the original source-suite runner. Validate its frozen data without model calls using `.venv/Scripts/python.exe -m evals.experience`.

The [V1/V2 pilot results](evals/EXPERIENCE_PILOT_RESULTS.md) explain every test with actual replies, recommended products, objective checks and separately labeled qualitative assessments, followed by a short conclusion.

The four source datasets contain 167 cases at implementation time: 65 deterministic CSV rows, 32 behavioral conversations, 52 adversarial conversations and 18 Hebrew cases. The loader derives counts and stable identities from the files. Source expectations remain V1 compatibility labels.

`datasets/v2/expectations.jsonl` records changed V2 expectations, rationale and review status. `relevance.jsonl` contains draft semantic pairs; drafts are not human-reviewed ground truth. `splits.json` groups development/regression cases and records whether independent prospective holdout cases exist. Historical files in `datasets/answers/` are reference outputs, not fresh evaluation evidence.

At the final evaluation stage:

```powershell
.venv/Scripts/python.exe -m evals.feasibility
.venv/Scripts/python.exe -m evals.run_evals --live
.venv/Scripts/python.exe -m evals.langsmith_experiment <evidence-directory>
.venv/Scripts/python.exe -m evals.monitor
```

Live replay makes paid calls to `gpt-6-luna` with explicit concurrency and one SDK retry. It resets state between cases, replays all turns, retains turn-level facts and aggregates invariant failures across the conversation. Reports include execution failures, source/difficulty slices, legacy metrics and draft V2 metrics. Complete grounding and task success remain unknown without reviewed semantic judgments.

Currency rates in evaluation default to the versioned `datasets/v2/exchange_rates.json` fixture. Add `--live-rates` to `evals.run_evals --live` only for a deliberate current-rate experiment. Each output records its quote, source, reference date and fetch time; scoring uses that recorded quote without network access. Archives from before this extension use the original frozen fixture. Runtime has no fixed-rate fallback.

Local evidence lives in ignored `evals/artifacts/`. The LangSmith upload command publishes an immutable dataset and experiment over recorded outputs; it does not call the model again. Runtime events and the local HTML monitoring view live in ignored `monitoring/`.

Use `.venv/Scripts/python.exe -m evals.rescore <evidence-directory>` to apply scorer fixes without making model calls or overwriting the original run. It creates a `rescored/` child directory and records scorer provenance. The final source-case evidence is in `evals/artifacts/v2-final-verified/rescored/` and its filtered monitoring view is `monitoring/v2-final.html`.

Scoring distinguishes ordinary Recall@10, its catalog-dependent ceiling, achievable Recall@10, Hit@10, precision/coverage, and graded nDCG. Unknown relevance judgments remain unknown. Calibration only accepts reviewed development labels:

```powershell
.venv/Scripts/python.exe -m evals.calibrate --output retrieval-config.json
```

Pass a calibrated configuration to the runner using `--config retrieval-config.json`. Runtime configuration uses the explicit `RetrievalConfig` defaults until a measured configuration is adopted. No semantic release result is claimed merely because unit tests pass.
